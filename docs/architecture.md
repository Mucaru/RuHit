# Architecture decision record

## ADR-001: Native Vite multi-page application instead of Astro

**Decision:** Keep Vite and use one real HTML entry per public route; share React bundles and components between those pages.

**Reasoning:**
1. The project already uses Vite/React, so no framework migration or new server runtime is required.
2. Vite's multi-page build emits real HTML documents; ordinary anchors provide native Back/Forward behavior without `pushState` or a client router.
3. Cloudflare serves one static directory (`dist/public`) and the service worker can precache every route. This removes Express and duplicate deployment paths.

**Trade-off:** Route HTML is generated by `scripts/generate-routes.mjs`; route generation must run before Vite dev/build. If route-specific server rendering or content collections become a real requirement, revisit Astro.

## ADR-002: Pure TypeScript question engine

Generators receive a random source and return parameters, prompt, expected answer, explanations, hints, misconception feedback, and a visual hint. `solveQuestion()` calculates the answer in a separate switch over the same parameters. Property tests compare both paths across deterministic seeds.

## ADR-003: Local-only progress

Progress schema v2 is validated and clamped on read. A one-way migration reads the old v1 key and writes v2. No user identity is required; the service worker only caches static app assets.
